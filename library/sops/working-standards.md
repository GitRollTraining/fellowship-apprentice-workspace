# Working standards

Four rules that govern everything written in this workspace. They are short on purpose.

## 1. Sourced, not generated

Every assertion of fact traces to a source you can point at. The agent organises and explains; it does
not author facts.

The operative boundary, because it is the part people get wrong: **facts must be sourced; pedagogy
scaffold may be generated.** Sequencing, connective explanation and exercise wording assert no new fact
and may be written. "The owner approves invoices over 500 dollars" is a fact and needs a place in the
session record it came from.

## 2. Nothing raw reaches the reader

A transcript, a screenshot dump or an unedited export is not a deliverable. Everything is parsed,
checked and composed before anyone outside the engagement sees it.

## 3. Scaffolds, not textbooks

Teach the floor and the map. Exhaustive coverage of a tool that turns over annually is work you will
throw away.

## 4. A code never stands alone

Write the thing. If a code helps with filing, it goes in brackets *after* the thing, never instead of
it. `D-24` is not a sentence; "rebuilding a process from start to finish [D-24]" is.

The test for any sentence: if reading it requires looking something up, rewrite it or cut it.

**The corollary, and it is the opposite instinct:** DEFINE a term, never RENAME it. Substituting a
friendlier synonym for a defined term does not remove a lookup, it creates a translation problem
between your document and every other document. `competency` costs one clause to define — *something a
fellow can be watched doing on a real task, producing an artifact you can point at* — and is then free
for the rest of the document.
